# Directory Submission Checklist

Use this when submitting to agent-skill directories, awesome lists, MCP registries, or tool collections.

## Before submitting

- [ ] The directory/list is active (PR merged or updated in the last 3 months).
- [ ] The directory accepts external submissions (check CONTRIBUTING.md or recent PR history).
- [ ] The directory's scope matches the repo's job-to-be-done.
- [ ] Commercial / open-core projects are allowed (check rules).
- [ ] No existing entry for the same project exists (check for duplicates).
- [ ] A short description exists in `.repo-growth/assets/` (100–200 chars).
- [ ] A long description exists in `.repo-growth/assets/` (1–2 sentences).

## The submission

- [ ] Follow the directory's exact format (alphabetical order, link format, description length).
- [ ] Description is neutral — avoid "best", "fastest", "easiest", "most powerful".
- [ ] No tracking links or UTM parameters.
- [ ] Commercial affiliation is transparent (if required by the directory).
- [ ] PR title follows conventional commits format (`docs: add owner/repo to ...`).
- [ ] PR body explains *why* the addition fits the directory's scope.

## After submitting

- [ ] PR URL logged in `.repo-growth/prs.jsonl`.
- [ ] Target status updated in `.repo-growth/targets.yaml`.
- [ ] Follow-up scheduled if no response in 14 days (one polite ping only).
- [ ] If rejected, learn from the reason and log in `decisions.md`.

## Directories to consider

For agent-skill repos:

- Awesome lists on GitHub matching the repo's category.
- MCP server / tool directories.
- Agent-skill registries (Claude Code, Codex, etc.).
- Community-curated resource lists in adjacent tool ecosystems.
- DevRel and open-source tool collections.
