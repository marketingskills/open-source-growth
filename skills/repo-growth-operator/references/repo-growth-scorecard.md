# Repo Growth Scorecard

Score each dimension from 0 to its max weight. Total = /100.

## Positioning (0–15)

| Criterion | Points |
|---|---|
| One-line value prop is in the README title/description | 3 |
| The repo name and description match the actual job-to-be-done | 3 |
| The README hero section (first screen) explains *why* this exists | 3 |
| A specific audience is named | 3 |
| The repo is clearly different from alternatives | 3 |

## Install flow (0–15)

| Criterion | Points |
|---|---|
| One-command install exists above the fold | 5 |
| Install works without manual steps | 4 |
| Prerequisites are documented | 3 |
| Verification step (`skills list` or equivalent) is shown | 3 |

## First useful output (0–15)

| Criterion | Points |
|---|---|
| A "try this first" prompt is in the README | 5 |
| The example prompt produces useful output in < 30 seconds | 5 |
| Expected output is shown (screenshot or transcript) | 5 |

## Demo / proof (0–10)

| Criterion | Points |
|---|---|
| Terminal GIF or video demo exists | 4 |
| Animated demo shows the full workflow | 3 |
| Real output screenshots in README | 3 |

## Repo trust (0–10)

| Criterion | Points |
|---|---|
| License file present | 2 |
| CHANGELOG exists | 2 |
| Issue templates configured | 2 |
| CI passing badge visible | 2 |
| Release tags are used | 2 |

## Contribution path (0–10)

| Criterion | Points |
|---|---|
| CONTRIBUTING.md exists | 3 |
| Good-first-issue labels used | 2 |
| Pull request template exists | 2 |
| Roadmap or future plans documented | 3 |

## Skill metadata (0–10)

| Criterion | Points |
|---|---|
| Each SKILL.md has a clear `name` | 2 |
| `description` explains the job-to-be-done | 2 |
| Trigger phrases are specific | 2 |
| Example prompts are included | 2 |
| Dependencies / safety notes documented | 2 |

## Distribution assets (0–10)

| Criterion | Points |
|---|---|
| Launch posts (LinkedIn, X) drafted | 3 |
| Demo script exists | 2 |
| Directory submission checklist exists | 2 |
| Hacker News / Reddit pitch drafted | 3 |

## OSS-to-paid path (0–5)

| Criterion | Points |
|---|---|
| Free vs paid boundary is clear | 2 |
| Paid CTA is in README | 1 |
| Self-hosted option exists | 1 |
| Upgrade path is frictionless | 1 |
